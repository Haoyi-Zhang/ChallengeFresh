# Venue pattern matrix

This matrix records explanatory and evidentiary patterns from twelve full TDSC papers. It is a writing-calibration instrument, not a citation-count or quality ranking. Bibliography bands are used where an exact final reference number was not needed for any scientific claim; exact counts are recorded only where they were directly checked. No paper text or outline was copied.

## Patterns adopted

The paper uses a concrete failure mode before definitions; separates latent dimension, response length and residual rank; states the threat/game model before the certificate; keeps core proofs in the main paper; includes a strong probability-preserving baseline rather than only a straw baseline; pairs exhaustive finite checks with negative controls; and gives one consolidated limitations section. Figures are used only for data-derived precision and sensitivity, while tables carry model distinctions and campaign scope.

## Patterns deliberately not adopted

The paper does not imitate hardware-evaluation breadth, because no device data exist. It does not present a protocol message-flow diagram, because the result is a conditional certificate rather than a new AKE protocol. It does not infer source entropy, reliability, or unclonability from synthetic finite checks. It also does not inherit security claims from protocols later attacked in the literature.
